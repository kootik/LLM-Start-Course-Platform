# Домашнее задание 2: Обработка данных в n8n

**Цель:** Закрепить навыки работы с узлами Filter, Sort, Merge, Aggregate в n8n.
**Срок сдачи:** 7 дней
**Формат:** Экспортированный JSON файл workflow.

---

## ДЗ 2.1: Создать workflow по фильтрации

**Описание:**
Создайте workflow, который получает список продуктов, фильтрует их по цене и сортирует.

**Шаги:**
1.  **Получение данных:** Получите список продуктов (используйте любой Mock API, например `https://dummyjson.com/products` или `https://fakestoreapi.com/products`).
2.  **Фильтрация:** Отфильтруйте товары, цена которых дороже **$50**.
3.  **Сортировка:** Отсортируйте оставшиеся товары по названию (в алфавитном порядке А-Я).
4.  **Лимит:** Оставьте только **Топ-20** товаров после сортировки.
5.  **Сохранение:** Сохраните результат в Google Sheets (или сымитируйте сохранение выводом в консоль, если нет доступа к Google API).

**Требования:**
- [ ] Workflow работает без ошибок.
- [ ] Все 5 узлов (HTTP, Filter, Sort, Limit, Google Sheets/Log) используются.
- [ ] Результат корректно отфильтрован.
- [ ] Workflow экспортирован в JSON.

## ДЗ 2.2: Реальный кейс - Обработка заказов

**Сложность:** High (Высокая)
**Время выполнения:** 3-4 часа

**Описание:**
Симулируйте процесс обработки заказов в интернет-магазине. Вам нужно объединить данные из разных источников и подготовить отчет.

**Сценарий:**
1.  **Получение заказов:** Получите массив заказов из API (создайте Mock Data с полями `orderId`, `customerId`, `amount`, `status`).
2.  **Фильтрация:** Отфильтруйте только **незавершённые** заказы (статус `pending`).
3.  **Объединение (Merge):** "Подтяните" данные о клиентах (Merge по `customerId` с другим Mock API или набором данных).
4.  **Агрегация:** Посчитайте общую сумму заказов и количество заказов для каждого статуса (или сгруппируйте по клиентам).
5.  **Отчет:** Отправьте итоговый отчет (например, "Клиент X имеет 3 активных заказа на сумму Y") по email (используйте Gmail node или просто Log).

**Критерии успеха:**
- Корректное использование узла `Merge` (объединение данных).
- Правильная логика фильтрации статусов.
- Читаемый итоговый отчет.
